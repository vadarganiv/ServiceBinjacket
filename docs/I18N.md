# Internationalization

## Locales and routes

- `sq`: Albanian, primary and default
- `en`: English, secondary
- `/` redirects to `/sq`
- Public routes are prefixed with `/sq` or `/en`
- `/admin/*` is currently English-only and has no locale prefix

`frontend/proxy.ts` applies next-intl routing to public page requests while leaving API, framework asset, file, and admin paths outside locale rewriting.

## Translation files

```text
frontend/messages/sq.json
frontend/messages/en.json
```

Both files should contain the same key structure. Public UI copy belongs in translation messages; backend error codes can be mapped to localized frontend messages when user-facing wording is needed.

## Database content

Products, services, categories, and image alt text use `*Sq` and `*En` columns. Application mappers select the requested locale. For `locale=en`, an empty English field falls back to Albanian; missing/invalid locale input defaults to `sq`.

Localized slugs are resolved by their corresponding public detail endpoints. When adding a language switch on an entity detail page, resolve the target slug by entity identity rather than replacing only the URL prefix.

## Review checklist

1. Albanian and English message files have matching keys.
2. New public text is translated in both files.
3. Albanian copy is reviewed by a fluent speaker before a real public launch.
4. Titles and descriptions are localized.
5. Canonical and `hreflang` links point to the real HTTPS domain.
6. English database fields intentionally fall back rather than showing blanks.
